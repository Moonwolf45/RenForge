# Журнал решений и подводных камней

Хронология ключевых технических решений и граблей. Дистиллировано из рабочей истории.
Новые важные решения дописывать сюда с пометкой контекста.

## Окружение и рабочий процесс

- **ОС/шелл:** Windows, PowerShell/cmd. Кириллица в inline-выводе консоли мангалится
  (файлы в UTF-8 целы). Для Python-скриптов — писать файлом (fs_write) + запускать
  venv-питоном, не инлайнить кириллицу в команду.
- **Ложный exit 1:** `git`, `cargo`, PyInstaller дают exit code 1 из-за шума на stderr,
  будучи УСПЕШНЫМИ. Смотреть на реальные маркеры (`Finished`, `main -> main`,
  `completed successfully`), не на код возврата.
- **Префикс `rem ;` в командах НЕ нужен** (был глюк мангалинга в одной из сессий, не
  воспроизводится).
- **Сборки:** фронт — `npm --prefix "...\renforge" run build`; Rust — 
  `cargo check --manifest-path "...\src-tauri\Cargo.toml"`.
- **venv PyInstaller:** `d:\Renforge\Renforge\extractor\venv\Scripts\python.exe`.
- **Билд по фиксам (политика владельца):** полный `tauri build` — только к релизу. По ходу работы:
  фронт — ничего (владелец тестирует в dev, Vite HMR подхватывает вживую); Rust — только
  `cargo check` (проверка компиляции, `tauri dev` пересоберёт сам); **Python-сайдкар —
  обязательная пересборка + деплой в `bin/`**, т.к. приложение (в т.ч. dev) вызывает
  скомпилированный `bin/rpyc_extractor.exe`, а НЕ `.py` (иначе в dev тестируется старое поведение).
- **CHANGELOG ведёт агент** — обе версии (ru + en, секция «в разработке»); владелец вычитывает
  и правит перед коммитом.
- **Тестовые игры:** `D:\Renforge\Игры для тестов\` (Katawa Shoujo — легаси Ren'Py 6.10.2e).

## Правила от владельца (foulnike)

- Работать на русском. **Никаких эмодзи в UI.**
- **Локали — все 6 языков синхронно** (ru/en/zh/ja/es/pt) при любом изменении текстов.
- **Коммиты RenForge держать** — мы в работе над 1.3, владелец сам решает когда коммитить.
  (AniMori — отдельный проект, там коммитили по ходу; RenForge — нет.)
- После правок кода — собирать для проверки. Владелец сам тестирует в dev.
- Для крупных фич — сначала дизайн/риски, спрашивать «го». Мелкие — сразу делать.
- **БД пользователей можно трогать** («мне пофиг на бд юзеров, делай надёжно») — но
  надёжно и идемпотентно (ADD COLUMN с игнором дубля, миграции без потери данных).
- Честность про незавершённость и риски; контраргументы если владелец не прав.
- Есть постоянный тестер (пришёл ещё с 1.1) — транслирует баги/фичи через владельца.

## Архитектурные решения и грабли

### Извлечение (экстрактор)
- **AST по .rpyc — основной путь**, регекс по .rpy — фоллбэк. Регекс НЕ убирать
  (рискованно), даже несмотря на дубли в pure-.rpy кейсах.
- **`extract_engine_common`** (регекс по `renpy/common/*.rpy`) — ОСТАВЛЯТЬ: таргетная
  добыча игроцентричных движковых строк (Сохранить/Выход/даты), AST берёт их хуже.
  Только при source=original; чёрный список внутренних файлов; дедуп.
- **Метка способа извлечения `source` (ast/regex)** — сквозное поле: экстрактор →
  `ExtractedString`/`DbEntry` → колонка `source` в БД → тег в шапке блока редактора
  (AST = акцент, Regex = янтарный). Диагностика надёжности строки.
- **Кодирование пиклов:** и наш `unpickler.py`, и вендоренный unrpyc грузят пиклы как
  `latin-1` (не ASCII!). Старые игры (Ren'Py 6.x, Python2-пиклы) держат не-ASCII байты
  в коротких binstring → ASCII/strict падает с UnicodeDecodeError. latin-1 декодирует
  любой байт 1:1; юникод-текст (BINUNICODE/UTF-8) от этого не страдает. Фикс unrpyc —
  в `decompiler/renpycompat.py` (`pickle_safe_loads`).
- **Имена файлов в UI — `.rpy`, не `.rpyc`:** Ren'Py зашивает оригинальное имя исходника
  (`.rpy`) внутрь скомпилированного `.rpyc`. Экстрактор берёт `node.filename` из AST →
  показывает `.rpy`. Это логическое имя (им оперирует и сам Ren'Py, и переводчики), НЕ
  ссылка на файл на диске. Тег остаётся даже когда физических .rpy нет.

### Доставка (delivery)
- **Распаковка .rpa → архив ОТКЛЮЧАЕТСЯ** переименованием в `*.renforge-disabled`
  (обратимо). Причина: Ren'Py грузит модули И из .rpa, И из loose-копий → каждый
  init/translate-блок выполняется ДВАЖДЫ; для строковых переводов это фатально
  (`StringTranslator.add()` падает на дубликате). Восстанавливать .rpa нельзя, пока
  рядом лежат loose-файлы.
- **build_runtime_rpy пропускает идентичные пары** (`original == translation`) как no-op.
- **build_runtime_rpy доставляет и `outdated` (1.3, вариант B):** перенесённые (fuzzy) и
  подставленные из памяти (`tm_fill`) строки раньше НЕ попадали в игру до ручной отметки
  «проверено» — тихо + catch-22 (их нельзя проверить в игре по Shift+R, т.к. не доставлены).
  Теперь доставляем `status IN ('translated','outdated')`; `BuildCounts.review` считает
  доставленные outdated-оригиналы и показывается в отчёте сборки («требуют проверки: N»).
  Жёлтая пометка в редакторе (`prev_original`) не трогается — трекинг ревью сохранён. Безопасно:
  те же предохранители (`[var]`-гард, no-op-скип). Побочный плюс: свежесмигрированный проект
  (всё fuzzy) теперь собирается, а не падает «нет переводов».
- **`escape_py_double` экранирует U+2028/U+2029** (1.3): не ради CPython (он их в литерале
  терпит), а ради построчных лексеров (`str.splitlines()` / Ren'Py читает .rpy построчно) —
  сырой символ мог разорвать логическую строку и уронить весь файл доставки. `\u2028` даёт
  тот же рантайм-символ, значение перевода не меняется.
- **Пометка дубликатов в редакторе (1.3):** `get_duplicate_originals` + `dupMap`. Т.к. доставка
  дедуплицирует по тексту, у строк с одинаковым оригиналом перевод общий (бейдж-счётчик), а
  разные непустые переводы = конфликт (#3, доставится один) → бейдж «!» + предупреждение
  `dup_conflict`. Грабля: `dupMap` отражает СОХРАНЁННОЕ состояние (грузится при открытии файла и
  после save) — несохранённые правки в конфликт-детекте видны только после сохранения.
- **Диагностика покрытия (opt-in, roadmap 0.1):** чтобы измерять, что доставка НЕ покрывает,
  собранный мод в диагностическом режиме логирует непокрытый текст на семантических горлышках
  (say-фильтр / `translate_string` / `renpy.input` / `renpy.ui.text`). Решения: (1) хелпер
  `_renforge_log_uncovered` ОПРЕДЕЛЯЕТСЯ ВСЕГДА — реальный или `pass`-no-op — шаблоны каналов зовут
  его безусловно (чище условной инъекции вызовов). (2) Логируем ВСЕ промахи сырыми, а классификацию
  «видно, но нет в базе» делаем в Rust (`read_uncovered` сверяет с БД), не в инжектированном коде —
  питон в игре остаётся тупым и crash-safe. (3) Формат — таб-разделённый экранированный текст, не
  JSON (не тащить парсер-допущения в рантайм; Py2/Py3-safe). (4) K6 пишет `ui`-промах только если
  игра сама не перевела (`_renforge_ts_orig(s)==s`) — иначе шумели бы строки, что движок переводит
  своим механизмом. Всё в try/except; лог в `config.basedir/renforge_uncovered.log`. Отчёт — модалка
  «Непокрытый текст» (см. 04), фильтр «кандидаты» = `in_db=false`, добавление в ручные одним кликом.
- **Предупреждение о мультиязычной коллизии (roadmap 1.2):** если целевой язык ∈ встроенных языков
  игры (`available_languages`), наш перевод может наложиться на штатную локализацию — UI-инъекция идёт
  в `translator.strings[target]`, а языконезависимые K1/K6 применяются поверх; если игрок выберет этот
  язык в меню игры, будет двойной/конфликтующий перевод. Детект — computed `targetLangCollision` в
  сторе (точное сравнение без регистра, 'original' исключён → без ложных срабатываний); UI — постоянный
  янтарный баннер на дашборде (НЕ тост: заметнее и не назойливо). Доставку НЕ трогаем — только предупреждаем.
- **Канал 4 (roadmap 1.1) уже реализован — это K6.** `RENFORGE_EARLY_HOOK` перехватывает `store._`,
  `store.__`, `renpy.translation.translate_string` (языконезависимо, по ui_map) — ровно то, что описывал
  1.1. Остаток (низкий приоритет): K6 сохраняет оригинал только `_` и вешает синглульную обёртку и на
  `__`; реальный `__` (в Ren'Py — отдельная функция перевода) теряется, а фоллбэк `_renforge_ts_orig`
  не обёрнут в try. Закалка на будущее, не новый пункт.
- **Собственные файлы доставки:** `00_renforge_patch.rpy/.rpyc`,
  `renforge_translations.rpy/.rpyc`, `renforge_font_*.ttf`, `renforge.db` (runtime-БД).
- **`is_renforge_workfile`** (фильтр экспорта «Полная игра») намеренно НЕ считает
  `renforge_translations.rpy` служебным — там он часть мода. А вот `list_game_files`
  (модалка «Файлы игры») эти сгенерированные скрипты ОТФИЛЬТРОВЫВАЕТ (не исходники игры).

### База данных
- Одна БД на **пару языков** (`.renforge/<source>-<target>.db`); указатель
  `.renforge/active` = активная пара; `.renforge/built` = чья сборка сейчас в game/.
  Legacy-фоллбэк `project/renforge.db`. Флаг `built_dirty` в project_meta.
- **Жалоба на битую БД с 1.1** была — поэтому все схема-изменения строго идемпотентны.
- Колонки эволюционировали: `prefix`, `prev_original`, `channel`, `confirmed`, `source`
  добавлялись через `ALTER TABLE ADD COLUMN` (дубль-ошибка игнорируется).
- **`confirmed`** — ручная отметка «перевод подтверждён» для строк где перевод == оригиналу
  (…, имена, числа). Иначе вечно «непереведённые». Подтверждение пустой строки →
  авто-заполняет оригинал. build пропускает идентичные пары.

### Фронт
- **Реактивность статусов:** бэкенд ставит `built_dirty`/статусы, но фронт должен
  ПЕРЕЧИТЫВАТЬ (`loadPairs()` в saveFile/deleteManualString/addManualString) — иначе
  бейдж «собрано/изменено» не обновлялся.
- **Скролл/навигация:** `scrollToBlock(id)` в store.js финализирует высоты всех textarea
  (фикс промаха из-за ленивого автороста), центрирует через `behavior:'instant'` — ВАЖНО:
  `.editor-panel` имеет `scroll-behavior:smooth`, поэтому `'auto'` подхватывает smooth,
  нужен именно `'instant'`. Вспышка `flashBlock`/`.row-flash`.
- **Диагностики — единый реестр `diagnostics.js`** (RULES): missing-tag/extra-interp =
  error, ui-overflow = warning. `diagnose()` мемоизирован (кэш с лимитом). Автофиксы:
  `stripLeadingPrefix` (срезает ведущее эхо `[ENGINE]:`), `restoreLeadingToken`
  (восстанавливает ведущие `{..}/[..]`), `wrapToFit`. `actions.js` делегирует в реестр.
- **Индикатор «Проверка» в шапке** — иконка-состояние: `!` (ошибки, красный) / `?`
  (предупреждения, янтарный) / `✓` (чисто). Специфичность `.btn.qa-*` чтобы перебить
  `.btn-secondary`.
- **Центрирование вкладок шапки:** сегмент-контрол съезжал вправо на широком экране —
  left был `flex:1`, right `flex:0 0 auto` (несимметрично), центр центрировался по остатку,
  а не по всей ширине. Фикс: left/right → `flex:1 1 0` (равный рост от базы 0), center →
  `flex:0 1 auto` (по контенту). Кнопки не сжимаются (`flex-shrink:0`), правая секция не
  наезжает на соседей.
- **Подложка лайтбокса галереи:** жёсткая шахматка → мягкая тематическая (`color-mix(
  var(--text-main) 6%)` над `--bg-base`) + переключатель `checker/dark/light` (localStorage)
  для оценки прозрачных PNG.
- **CSS-токены:** семантические `var(--*)`; янтарный для предупреждений — `#eab308`
  (используется в qa-warn/diag-warning). Точки статуса в редакторе — насыщенные цвета
  (#ef4444/#22c55e/#f97316/#eab308) + мягкое свечение (были тусклые пастельные токены).
- **Аудио:** единый ползунок громкости + двусторонняя синхронизация плееров через
  `volumechange` (защита от зацикливания сравнением по допуску), хранение в localStorage.
- **AI-модалка:** авто-зачистка префиксов-эхо во всех пачках через `stripLeadingPrefix`.
  **Аудит:** жалоба «промт следует только первой пачке» по коду НЕ воспроизводится —
  `runChunked` строит и шлёт полный system-промт в КАЖДОЙ пачке (per-chunk `buildSystem` +
  `sendFn(system,…)` для Ollama и API); уточнить у тестера, о чём была жалоба.

## Отложенные / открытые пункты
- **Замена регекс-строк на AST при переизвлечении** (дубли pure-.rpy) — отложено. План А:
  id-префикс `rpyfb_` для регекс-строк + чистка при AST-извлечении + перенос переводов
  через TM. Владелец думает.
- **Массовый импорт строк** (round-trip к пофайловому экспорту CSV/JSON/PO) — отложен.
- **Мёртвый Vue Flow** (CSS-блок в `style.css` строки 565–598 + 4 `@vue-flow/*` в package.json) —
  подтверждено аудитом (ни классы блока, ни `@vue-flow` не используются в `.vue`/`.js`), вычистить.
- **`renforge_cli` standalone** не собирается (нужен рефактор `renforge_core`) — dev-only.
- **Репорт пропущенных файлов из экстрактора** (требует пересборки сайдкара) — не начат.
- **~~Принудительная отправка промта в каждой пачке AI-перевода~~ — по коду УЖЕ ДЕЛАЕТСЯ**
  (аудит): `runChunked` шлёт полный system-промт в каждой пачке (Ollama `system` / API
  `messages[system]`). Жалоба либо устранена рефактором на чанки, либо про иное — уточнить у тестера.
