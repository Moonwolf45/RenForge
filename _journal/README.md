# RenForge — Журнал проекта

Внутренняя дев-документация RenForge (Tauri 2.0 / Vue 3 + Rust). Живой журнал:
поддерживается в актуальном состоянии **при каждом изменении кода**. Не входит в
публичный репозиторий (лежит вне `renforge/`, рядом с `_testbench/`).

## Зачем это
Чат-контекст ограничен и периодически сжимается — нюансы решений теряются. Журнал —
внешняя долговременная память: архитектура, назначение и логика каждой функции, а также
причины конкретных технических решений («почему так, а не иначе»).

## Соглашения ведения

- **Язык — русский.** Пишем плотно и по делу, без воды.
- **Обновляем в том же ходе, что и код.** Изменил функцию → правишь её карточку здесь.
- **Формат карточки функции:** имя/сигнатура → что делает (1–2 строки) → ключевые нюансы/
  подводные камни → связи (кто вызывает / что дёргает).
- **«Почему», а не только «что».** Причина решения важнее описания поведения — поведение
  видно в коде, а причина забывается.
- **Ссылки на файлы** — относительно корня репо `renforge/` (напр. `src-tauri/src/lib.rs`).
- **Новое важное решение** → строка в `06-decisions-log.md` с датой.
- **Не дублируем код.** Журнал — карта и мотивация, а не копия исходников.
- **Changelog:** каждое пользовательское изменение → строка в `CHANGELOG.md` **и**
  `CHANGELOG.en.md` (в репо, синхронно ru/en) в секцию текущей версии. Формулировки —
  для пользователя, не внутренним жаргоном. Внутренние детали/причины — в журнал (07/08).

## Как пользоваться (для агента в новой сессии)
1. Прочитать `00-overview.md` — общая картина.
2. Прочитать `06-decisions-log.md` — контекст решений и грабли.
3. Прочитать `07-worklog.md` — где мы сейчас, что не закоммичено.
4. По конкретной задаче — соответствующий модульный файл (01–05).
5. При работе с извлечением/доставкой/легаси-движками — обязательно `08-edge-cases.md`
   (эмпирическое поведение, которого нет в коде).
